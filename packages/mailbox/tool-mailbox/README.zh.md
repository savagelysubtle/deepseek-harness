# @deepseek-ai/dsh-tool-mailbox

[English](README.md) | 中文

注册在 `ctx.mailbox` 接缝之上的三个模型可见邮箱工具——`mailbox_send`、`mailbox_check_inbox` 与 `mailbox_await`。每个工具都经同一条身份路径解析调用席位的地址：部署提供的受信会话名，折入调用代理的会话 id，由 `resolveMailboxIdentity` 解析。席位可以把邮件发往任何地方，但只能是自己；没有可伪造的 `from` 参数，也没有可读他人队列的地址参数。匿名运行（无受信名可用）在调用时响亮失败，绝不回退到猜测的发送者。

需要一个已加载的邮箱 Service Provider（如 `@deepseek-ai/dsh-mailbox-local`）注册为注册表的 `defaultProvider`；注入的服务齐备之前插件保持 pending。

## 工具

### `mailbox_send`

| 参数 | 类型 | 说明 |
|---|---|---|
| `to` | string（必填） | 收件席位的裸名；在准入边缘做文法校验。 |
| `subject` | string（必填） | 简短的人类可读主题行。 |
| `body` | string（必填） | 消息文本；须自足，因为收件人可能没有这段对话的上下文。 |
| `blocking` | boolean | 发送者被阻塞等待答复时为 true；投递时渲染为 blocking 契约行。 |
| `replyToTraceId` | string | 本回复所答复消息的 traceId——当对方正等待它时提供。把回复穿透到那条关联链上，等待席位的 `mailbox_await` 才能匹配到它。 |

结果携带提供方 id、双方地址与该行的关联 id——普通发送是新铸的 id，穿透回复则是被等待发送的 id——渲染会点名该 id，模型由此能把它传给 `mailbox_await`。桥的单 trace 跳数上限约束一条穿透链可携带的已准入投递数；更长的往来改挂到新的一次发送上。

### `mailbox_check_inbox`

无参数。认领并落定（收件箱准入）发往调用席位自身地址的至多 20 条 pending 消息，返回排出的条目——发送者、blocking 标记、主题、正文、认领时间。

### `mailbox_await`

| 参数 | 类型 | 说明 |
|---|---|---|
| `deadlineMs` | integer | 钳制到 1000–600000；默认 300000。每次到期都把决定交还模型。 |
| `traceId` | string | 被等待发送结果里的关联 id。省略则在任何入站邮件到达时结束等待。 |

占住当前回合，直到回复到达、被等待发送被拒、或截止时间到期——这是临时拼凑 Bash sleep 轮询循环的替代品。拒绝立即以记录的原因原文结束等待。回复靠存储读取检测，而非只靠认领：桥已认领、已拼接为回合、已落定 `done` 的回复照样带内容结束等待，穿透的回复（`replyToTraceId`）被精确匹配到这次等待。超时是携带被等待发送存储状态的普通结果——`delivered`（附时间）、`claimed`、`pending` 或 `unknown`——外加 `waitedMs`。取消把调用者的中止透传进每次读取与每段睡眠，被停止的席位立即收回控制权。

## 模型体验

### 发送与排水

#### 模型看到什么

`mailbox_send` 的结果文本给出收件人、存储消息 id、发送者与关联 id，以及指向 await 该 id 的指引；`mailbox_check_inbox` 返回的条目与 `mailbox_await` 的渲染完全一致地编号，回复无论由哪个工具投递读起来都一样。没有系统提示分区，没有通讯录——结果文本就是模型的完整接口。

#### Token 影响

每次调用一条固定形状的短结果。`mailbox_check_inbox` 随排水量伸缩：每次调用至多 20 条，每条主题加正文，由排水上限而非队列深度约束。

#### KV Cache 影响

工具结果在调用会话中只追加；重复投递的回复（至少一次投递性质）只增加 token，不改动任何已缓存前缀。

### 等待回复

#### 模型看到什么

一条结果说明等待如何结束：回复的编号条目、拒绝的原因原文，或携带被等待发送存储状态的超时（`delivered` 附时间、`claimed`、`pending` 或 `unknown`）外加 `waitedMs`。被占住的回合会把席位的模型阻塞满钳制截止时间——边界是工具自己的，从不是调用者提供的预算。

#### Token 影响

一次有界等待只花一个被占回合加一条结果；临时拼凑的替代方案——反复轮询——每 2 秒烧一个回合。等待期间的读取只触达存储，从不触达模型。

#### KV Cache 影响

等待期间被占回合的请求历史保持冻结，缓存前缀因此存活到结果；超时文本的投递诊断以追加的结果文本到达，不是上下文重写。

## 已知限制与延期工作

- **未追踪或未穿透的回复按方向匹配，而非按 id。** 不带 `traceId` 的等待——或对端回复未带 `replyToTraceId` 的被追踪等待——在锚点（等待开始，或被等待发送的准入时刻）之后准入的任何入站邮件上结束。无关入站邮件因此也会结束这样的等待；条目会署名发送者，由模型自行判断。精确关联需要穿透，而只有回复一方能提供。
- **同一条回复可能两次到达模型。** 基于读的检测把回复内容作为工具结果返回，而桥把同一条回复拼接为回合——这是认领路径本就具备的至少一次投递性质。跨这两个通路的去重需要接缝今天尚不拥有的投递台账。
- **穿透链受桥的单 trace 跳数上限约束**（默认 8 次已准入投递）。拒绝会点名该 trace；恢复方式是一次新发送，它会开启新链。
