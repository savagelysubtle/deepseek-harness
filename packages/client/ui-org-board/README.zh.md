# @deepseek-ai/dsh-client-ui-org-board

[English](README.md) | 中文

组织架构图（SWD-134 第 2 阶段）在侧边栏已有的 `sidebar.footer.action` slot 中、紧挨着「全部停止 / 全部发送」注册了第三个条目：一个大型弹窗，基于 **React Flow**（`@xyflow/react`）把整个组织绘制成节点图。它只读取 host 端在第 1 阶段新增的 `org.get` RPC——本包内不存在任何编辑入口，也没有为编辑预留任何半成品接线；编辑属于后续阶段。每次打开弹窗时都会重新发起 `org.get`（弹窗内的「刷新」按钮同理），因此界面绝不会展示上一次打开之前的旧数据。

**节点即席位**（来自解析后的注册表）：每个节点显示席位名称，以及一行徽章，用于区分部门负责人、一次性的测试席位、差异报告判定为「已注册但未被两个名册都提供服务」的席位，以及拥有 call-up 权限（可致信任何席位）的席位——call-up 只渲染为该节点自身的一个徽章，绝不会画成连到其余所有席位的边，因为它是席位的一个属性，而不是拓扑关系。**边即无向的邮件权限对**，直接来自注册表自身的 edges 列表，绘制时不带箭头。点击某个节点会打开详情面板，展示其工作目录、会话 ID（若无则明确显示「未记录会话」）、以及工具允许/禁止列表（若均无则明确显示「无工具限制」）。节点位置来自固定的字母序网格布局（`layout.ts`）——注册表本身不携带坐标，而本阶段也没有可供拖拽位置持久化的地方，因此没有为这一个只读视图额外引入自动布局依赖。

**本包存在的核心目的：失败绝不能渲染成空白，也绝不能渲染成一块「干净」的看板。** `org.get` 的三个内层结果（`registry`、`mailboxBridge`、`toolMailbox`）及其差异报告各自独立失败，且各自在界面上显示自己的具体原因——绝不会用一块空画布代替「注册表读取失败」的提示，也绝不会悄悄省略差异区块来代替「没有可报告的差异」。具体而言：注册表不可读时会显示一条红色提示条并说明原因，且完全不渲染图形区域（而不是在其位置留一块空画布）；某个名册不可读时会显示它自己的提示条，同时差异区块会显示「差异不可用」而不是一份干净的报告（差异计算要求全部三个来源都成功，因此名册失败必然会连带出一条具名的差异失败提示——本包绝不会用部分读取结果重新计算或伪造出一份差异结论）；RPC 调用本身失败（传输或业务错误，在任何组织数据被返回之前）时只显示一条顶层提示，其余内容一概不显示，因为此时连 profile 名称都不存在。只要有任何响应到达，就会始终显示 profile 名称（`profile`）——因为当前部署中没有任何地方能在运行时得知当前使用的 profile；在这里显示出来，正是把这个「仅在源码里才能看到的假设」变成查看者本人也能看到的事实。

## 模型体验

无影响，本包只是把一个已有的只读 host 查询（`org.get`）投影出来供人查看；它从不触碰会话内容、提示词、工具 schema 或模型上下文。

#### KV Cache 影响

无影响；本包不发起任何 LLM 请求，也不会向任何会话日志追加内容。

## 已知限制与延后工作

- **只读** —— 本阶段有意如此。没有新增/删除/重命名席位、没有编辑边、也没有「修复」差异的操作；这些属于后续阶段的范围。
- **没有服务端推送失效通知** —— 面板只在打开时、点击「刷新」时以及重新连接时重新读取，不会响应服务端推送的事件；在另一个标签页中做的更改，要到上述任一时机才会反映出来。
- **图形库的基础样式表是内置副本，而非直接引入** —— 本构建流程没有处理裸 `.css` 引入的加载器，因此 `src/client/xyflow-base.module.css` 是 `@xyflow/react` 自带基础样式的一份包装副本。该依赖使用脱字号范围锁定，因此范围内的更新可能带来与这份副本不再一致的样式，而且不会有任何明显报错。每次升级 `@xyflow/react` 时都需重新生成——该文件的头部注释记录了具体步骤。
- **固定网格布局，不支持拖拽持久化** —— 节点按字母序排列在网格中，且不可拖拽；目前也没有地方可以保存一次拖拽后的新位置。
- **「已提供服务但未注册」的差异行只以列表形式呈现** —— 它们没有 `cwd`／`sessionId`／工具信息可显示，因此只会出现在差异区块的第二个列表中，不会作为图中的节点出现。
