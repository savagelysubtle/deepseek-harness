# @deepseek-ai/dsh-client-ui-org-board

[English](README.md) | 中文

组织架构图（SWD-134 第 2 阶段）在会话头部的 `conversation.session.header.actions` slot 中、紧挨着「全部停止 / 全部发送」注册了第三个条目（SWD-162 将三者一并从侧边栏底部移出）：一个大型弹窗，基于 **React Flow**（`@xyflow/react`）把整个组织绘制成节点图。它通过 `org.get` 读取注册表，并且只通过 host 的 `org.write` / `org.writeServed` RPC 写入。看板提供以下编辑操作，每一项都先经 `edit.ts` / `served-edit.ts` 中的纯函数预览再提交：添加席位（工具栏表单）、删除席位（需确认，并先列出会被级联删除的边）、在两个席位之间拖拽以添加邮件边、点击某条边将其删除（需确认）、编辑席位的工具允许/禁止列表，以及切换席位的已服务／未服务状态（需确认；同时写入两个已服务名册）。每次打开弹窗时都会重新发起 `org.get`（工具栏中的「刷新」按钮同理），因此界面绝不会展示上一次打开之前的旧数据。

**节点即席位**：每个节点显示席位名称，以及一行徽章，用于区分部门负责人、一次性的测试席位、差异报告判定为「已注册但未被两个名册都提供服务」的席位，以及拥有 call-up 权限（可致信任何席位）的席位——call-up 只是该节点上的一个徽章，绝不画成连到其余所有席位的边。**边即无向的邮件权限对**，直接来自注册表自身的 edges 列表，绘制时不带箭头。点击某个节点会打开详情抽屉，展示其工作目录、会话 ID（若无则明确显示「未记录会话」）、以及工具允许/禁止列表（若均无则明确显示「无工具限制」）。位置来自确定性布局（`layout.ts`），不持久化拖拽。席位按 `~/.dsh/org/registry.yml` 中每个席位可选的 `department` 行分入**部门分区**（非空，最长 48 个字符，手工编辑）。部门只是沟通分组，不代表职级。分区按字母序排列，没有部门的席位放在末尾的「未分配部门」分区；分区内先排负责人，再排其余席位，各自按字母序；负责人卡片不抬高、不放大。分区宽度取决于其席位数和随宽度调整的列数：画布宽度低于 640px 时为 2 列，640px 起为 4 列，1200px 起为 5 列，1500px 起为 6 列（未测量时为 4 列），列间距 232px、行间距 112px（卡片宽 208px）。分区按整列并排放置，一行放满后换到新的一层；席位很多的部门在分区内部按行折返。分区表面使用主题令牌（边框加半透明底色），标题显示部门名称和席位数；仅当筛选启用且分区内所有席位都已变暗时，该分区才变暗。分区不可选中。

**图表优先。** 弹窗与视口等高（`calc(100dvh - 48px)`，宽度最多 1800px），图表占满弹窗标题下方单行工具栏之外的剩余高度：工具栏依次为 profile 名称、「N drift」徽标（仅在差异数大于 0 时显示，点击可切换图表下方的差异列表）、席位筛选框、「添加席位」和「刷新」。图例为紧凑的一行。席位详情以覆盖式抽屉从右侧打开，可通过「关闭详情」按钮或 Escape 关闭（确认对话框打开时，Escape 交给该对话框处理）；在手机宽度（max-width 720px）下，弹窗铺满屏幕，抽屉变为底部面板。画布尺寸每次变化（`ResizeObserver`）以及列数或席位集合变化时，图表都会重新适配视图，且不重新挂载；桌面端在整个看板能以满卡片尺寸或更大显示时（例如 1920 宽）适配整个看板（React Flow `fitView`，padding 0.08，缩放限制在 0.6–1.2，`minZoom` 0.4）；否则按宽度适配，查看者滚动（滚轮平移；双指捏合或控件缩放）查看折叠线以下的分区层。手机端按宽度适配并锚定左上角，由查看者向下平移。界面显示 React Flow 的缩放／适配控件。邮件边仍然只为悬停或选中的席位绘制。

**卡片与筛选。** 卡片显示席位名称（14px，字重 600）和一行 12px 徽章，以及一个已服务／未服务状态圆点（`aria-label` 为「served」或「not fully served」；差异查询失败时完全省略，因此查询失败绝不会显示成一个绿点）。「可致信任何人」是中性的描边徽章。工具栏筛选框不区分大小写，按席位名称子串匹配，或将精确的 `lead`、`test`、`unserved` 词与席位的标志位匹配（`filter.ts`）；不匹配的席位会变暗（opacity 0.3）且不可点击，× 用于清除筛选。所有颜色都来自现有的 `--dsw-alias-*` 令牌，包括 React Flow 的画布、边、连接点和控件；本包中没有十六进制颜色字面量。

**本包存在的核心目的：失败绝不能渲染成空白，也绝不能渲染成一块「干净」的看板。** `org.get` 的三个内层结果（`registry`、`mailboxBridge`、`toolMailbox`）及其差异报告各自独立失败，且各自在界面上显示自己的具体原因——绝不会用一块空画布代替「注册表读取失败」的提示，也绝不会悄悄省略差异区块来代替「没有可报告的差异」。具体而言：注册表不可读时会显示一条红色提示条并说明原因，且完全不渲染图形区域（而不是在其位置留一块空画布）；某个名册不可读时会显示它自己的提示条，同时会有一条具名的差异提示条说明差异不可用（此时没有 drift 徽标和差异列表），而不是一份干净的报告（差异计算要求全部三个来源都成功，因此名册失败必然会连带出一条具名的差异失败提示——本包绝不会用部分读取结果重新计算或伪造出一份差异结论）；RPC 调用本身失败（传输或业务错误，在任何组织数据被返回之前）时只显示一条顶层提示，其余内容一概不显示，因为此时连 profile 名称都不存在。只要有任何响应到达，就会始终显示 profile 名称（`profile`）——因为当前部署中没有任何地方能在运行时得知当前使用的 profile；在这里显示出来，正是把这个「仅在源码里才能看到的假设」变成查看者本人也能看到的事实。

## 模型体验

无影响，本包只是把一个已有的只读 host 查询（`org.get`）投影出来供人查看；它从不触碰会话内容、提示词、工具 schema 或模型上下文。

#### KV Cache 影响

无影响；本包不发起任何 LLM 请求，也不会向任何会话日志追加内容。

## 已知限制与延后工作

- **空白／首屏时不显示** —— 承载该 slot 的会话头部在没有真实会话打开时不会渲染（SWD-162 设计决定），因此触发按钮会在没有会话打开时消失，这与旧版侧边栏底部始终可见的行为不同。
- **编辑能力有限** —— 只有上述编辑操作：不支持重命名席位，不支持编辑工作目录或会话 ID，不支持编辑 `callUp`，也不支持拖拽改变位置。差异只做报告，除按席位切换已服务状态外没有专门的「修复」操作。
- **没有服务端推送失效通知** —— 面板只在打开时、点击「刷新」时以及重新连接时重新读取，不会响应服务端推送的事件；在另一个标签页中做的更改，要到上述任一时机才会反映出来。
- **图形库的基础样式表是内置副本，而非直接引入** —— 本构建流程没有处理裸 `.css` 引入的加载器，因此 `src/client/xyflow-base.module.css` 是 `@xyflow/react` 自带基础样式的一份包装副本。该依赖使用脱字号范围锁定，因此范围内的更新可能带来与这份副本不再一致的样式，而且不会有任何明显报错。每次升级 `@xyflow/react` 时都需重新生成——该文件的头部注释记录了具体步骤。
- **确定性分区布局，不支持拖拽持久化** —— 节点排列在随宽度调整列数的部门分区中，且不可拖拽；目前也没有地方可以保存一次拖拽后的新位置。
- **「已提供服务但未注册」的差异行只以列表形式呈现** —— 它们没有 `cwd`／`sessionId`／工具信息可显示，因此只会出现在差异列表的第二个列表中（在「N drift」徽标展开时显示于图表下方），不会作为图中的节点出现。
