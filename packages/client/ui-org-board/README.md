# @deepseek-ai/dsh-client-ui-org-board

English | [中文](README.zh.md)

Org Board (SWD-134 slice 2) registers a third entry into the conversation session header's `conversation.session.header.actions` slot, beside Stop All / Send All (SWD-162 moved all three off the sidebar foot): a large modal drawing the organisation as a node graph, built on **React Flow** (`@xyflow/react`). It reads the registry through the host's `org.get` RPC (added in slice 1) and writes it only through the host's `org.write` / `org.writeServed` RPCs. The board offers these edits, each submitted through a pure preview in `edit.ts` / `served-edit.ts`: add a seat (toolbar form), remove a seat (confirmed, naming the edges it cascades over), drag between two seats to add a mail edge, click an edge to remove it (confirmed), edit a seat's tool allow/deny lists, and toggle a seat served or not served (confirmed; writes both served rosters). `org.get` is re-issued every time the modal opens (and on demand from the toolbar's Refresh button inside it), so the board never shows data from before the modal was last shown.

**Nodes are seats** (from the parsed registry): each node shows the seat name and a badge row distinguishing a department lead, a throwaway test seat, a seat the computed drift report says is registered but not fully served by both rosters, and a seat holding call-up (rendered as a badge on that one node, never as edges to every other seat — call-up is a property of the seat, not a topology). **Edges are undirected mail-permission pairs** from the registry's own edge list, drawn without arrowheads. Clicking a node opens a detail drawer with its working directory, session id (or an explicit "no session recorded"), and tool allow/deny lists (or an explicit "no tool restrictions"). Node positions come from a deterministic alphabetical grid (`layout.ts`) — the registry carries no coordinates, and this slice has nothing to persist a drag to, so no auto-layout dependency was added for one read-only view. The grid is width-aware: 2 columns below 640px of canvas width, 4 from 640px, 5 from 1200px, 6 from 1500px (4 when the canvas has not been measured, e.g. under jsdom), at a 232px column pitch and 112px row pitch with 208px-wide cards.

**The chart comes first.** The dialog is viewport-tall (`calc(100dvh - 48px)`, up to 1800px wide) and the chart fills whatever height is left under a single toolbar row beneath the modal title: the profile name, an "N drift" chip (shown only when drift is greater than 0; it toggles the drift lists below the chart), the seat filter box, Add seat, and Refresh. The legend is one compact line (one swatch per badge plus the edge note). Seat details open as an overlay drawer on the right, closed by its Close details button or Escape (Escape while a confirmation dialog is open is left to that dialog); at phone width (max-width 720px) the dialog is edge to edge and the drawer is a bottom sheet. The chart refits on every canvas size change (`ResizeObserver`) and whenever the column count or seat set changes, without remounting; on desktop it fits the whole grid (React Flow `fitView`, padding 0.08, zoom clamped to 0.6–1.2, `minZoom` 0.4), while on a phone it fits to width anchored at the top-left instead of fitting the whole grid (which would be too small to read), and the viewer pans down. React Flow's zoom/fit controls are shown. Mail edges still draw only for the hovered or selected seat.

**Cards and filter.** A card shows the seat name (14px, weight 600) and a row of 12px chips, plus a served/unserved status dot (`aria-label` "served" or "not fully served"; omitted entirely when the drift lookup failed, so a failed lookup never reads as a green dot). "May mail anyone" is a neutral outline chip. The toolbar filter matches case-insensitively as a seat-name substring, or as one of the exact words `lead`, `test`, `unserved` against the seat's flags (`filter.ts`); non-matching seats are dimmed (opacity 0.3) and not clickable, and × clears the filter. Every colour comes from existing `--dsw-alias-*` tokens, including the React Flow canvas, edges, handles and controls; the package contains no hex literals.

**The hard requirement this package exists to satisfy: a failure must never render as emptiness, and must never render as a clean board.** `org.get`'s three inner results (`registry`, `mailboxBridge`, `toolMailbox`) and its drift report each fail INDEPENDENTLY and each surfaces its own named reason on screen — never a blank canvas standing in for "the registry couldn't be read," and never a quietly-omitted drift section standing in for "nothing to report." Concretely: an unreadable registry shows a red banner naming the reason and the graph section is not rendered at all (no empty canvas in its place); an unreadable roster shows its own banner AND a named drift banner shows drift as unavailable (with no drift chip or lists) rather than a clean report (drift requires every source to have succeeded, so a roster failure always drops through to a named drift failure too — this package never recomputes or fakes a drift verdict from a partial read); the RPC call itself failing (transport/business error, before any org data was even returned) shows one top-level banner and nothing else, since there is no profile name to show either in that case. The profile name (`profile`) is always shown once any response lands, because the active profile is not discoverable at runtime anywhere in this deployment — naming it here is what turns that assumption from a fact only visible in source into one a viewer can see.

## Model Experience

None, as the package only projects an existing read-only host query (`org.get`) for human viewing; it never touches session content, prompts, tool schemas, or model context.

#### KV Cache effect

None; the package issues no LLM requests and appends nothing to any session log.

## Known Limitations and Deferred Work

- **Absent on the blank/hero screen** — the session header that carries this slot renders nothing until a real session is open (SWD-162 design call), so the trigger disappears exactly when no session is open, unlike the old always-visible sidebar foot.
- **Limited editing** — the edits listed above are all there is: no rename seat, no editing of working directories or session ids, no `callUp` editing, no drag-to-reposition. Drift is only reported, with no dedicated "fix" action beyond the per-seat served toggle.
- **No live push invalidation** — the board re-reads on open, on the Refresh button, and on a reconnect, not on a server-pushed event; a change made in another tab is not reflected until one of those happens.
- **The graph library's base stylesheet is vendored, not imported** — this bundler has no loader for a bare `.css` import, so `src/client/xyflow-base.module.css` is a wrapped copy of `@xyflow/react`'s own base styles. The dependency is pinned with a caret, so an in-range update can ship styles this copy no longer matches, with nothing failing loudly. Regenerate it on every `@xyflow/react` bump — that file's header comment carries the procedure.
- **Deterministic grid layout, no drag persistence** — nodes are placed in a width-aware alphabetical grid and are not draggable; there is nothing yet for a rearranged position to be saved to.
- **Served-but-unregistered drift rows are list-only** — they have no `cwd`/`sessionId`/tools to show, so they appear only in the drift lists' second list (rendered below the chart while the "N drift" chip is expanded), never as graph nodes.
