# @deepseek-ai/dsh-client-ui-org-controls

[English](README.md) | 中文

Org Controls 在侧边栏已有的 `sidebar.footer.action` slot 中、紧挨着「设置」注册了两个全局会话操作：**全部停止**（SWD-130）通过已合并的 `sessions.stopAll` host 调用，停止全部正在运行的顶层会话自身的回合，并级联停止各顶层会话下的整个子代理森林；它会读取返回的 `descendants` 结果，因此一旦级联出现 `{ failed }`，界面会明确显示为失败，而不会被折叠进「已停止 N 个」这样的成功提示里。**全部发送**（SWD-131）在同一个对话框中撰写一条消息，点击发送后立即、在回合中（绝不排队）把该消息发送给全部处于活跃状态的顶层会话，不再有单独的确认步骤（依据创始人裁决移除——撰写本身已经是一次明确的操作，可送达的会话数与「会打断当前回合」的提示都保留在撰写对话框里），通过全新的 `sessions.sendAll` host 调用；它同样会读取返回的 `result`，因此某个会话未能收到消息会明确显示出来，而不会消失在已发送计数里。两个控件用到的计数都来自框架标准的 `useSessions` hook——全部停止用「正在运行的会话数」，全部发送用「全部处于活跃状态（存在活动 agent）的顶层会话数」，而不是全部列出的顶层会话数：一个从未激活过的历史冷会话本就会被 host 端的广播逻辑跳过，如果计入计数，就等于承诺了一个控件实际无法送达的数字；当没有可操作的对象时，两个控件都会禁用触发按钮并显示明确原因，并且都用一个不会自动消失的结果提示条来呈现结果，而不是用 toast——因为部分失败正是那种绝不能在被看到之前就消失的信息。该包不提供 service，除这两个列表项外也不声明任何 Context 合并。约定：api-contracts v3 §8。

## 模型体验

间接影响，途径是本包这两个按钮触发的 host `session.stopAll`／`session.sendAll` RPC：全部停止会让正在进行的回合在产生更多输出之前结束，而全部发送所推送的消息会像普通输入框发送消息一样，直接进入模型读取的会话日志与下一回合上下文——但无论是 RPC 路由本身，还是它驱动的请求／回合组装，都不归本包所有。

#### KV Cache 影响

无直接影响；该包既不组装也不发送提供方请求。一条通过「全部发送」推送的消息会成为下一个请求包含的新日志内容，这会扩展提供方前缀而不是使其失效——与一条普通用户消息的效果相同，归属于组装该请求的会话／agent-loop 机制所有。

## 已知限制与延后工作

- **无法按会话排除** —— 两个控件都会作用于全部正在运行的顶层会话；此视图无法在一次「全部停止」或「全部发送」中排除某个会话。
- **全部发送不排队** —— 依据创始人裁决，这里是立即（回合中打断）而非排队在会话当前工作之后；这是有意为之的行为而非缺陷，但它意味着正在执行工具调用的会话会被打断，而不是先跑完当前调用。
