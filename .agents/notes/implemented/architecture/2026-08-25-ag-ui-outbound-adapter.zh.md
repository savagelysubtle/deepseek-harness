# Agent Note: AG-UI 出站适配器的位置与白名单

Status: implemented

[English](2026-08-25-ag-ui-outbound-adapter.md) | 中文

**Date:** 2026-08-25 · **Package:** `@deepseek-ai/dsh-ag-ui` · **Kind:** architecture/integration

## Problem

说 [AG-UI](https://docs.ag-ui.com) 的外部仪表盘需要观察某个会话的实时事件流，但 harness 没有能安全服务它们的表面。`ctx.webServer` 的约定是只服务浏览器、绑定回环且不认证的；从它那里服务一个外部的、非浏览器消费方，要么会削弱该服务器已声明的保证，要么必须按消费方类别把它的路由分叉。另外，harness 内部的会话事件词汇是可合并扩展的——任何插件都能新增事件种类——因此没有任何规则规定什么内容可以安全跨越进程信任边界抵达对外线路，默认全部转发的姿态有可能意外把仅限内部使用的载荷（例如提示词请求头、hook 内部细节，或未来携带凭据的事件）泄漏给外部消费方。

## Decision

外部仪表盘表面作为自己独立的可选插件发布，即 `@deepseek-ai/dsh-ag-ui`，拥有一个专属的 `node:http` 监听器，挂在 `POST /ag-ui/:threadId` 上，经由一份显式白名单把持久化会话事件翻译为 [AG-UI](https://docs.ag-ui.com) SSE 帧。翻译逻辑是一个纯模块（`src/translate.ts`）；传输层是一层薄壳（`src/server.ts`）；与 Cordis 的耦合只存在于 `src/index.ts` 中。

## 为什么用独立监听器而不是 web-GUI 服务器

`ctx.webServer` 的约定是只服务浏览器、绑定回环且不认证的；仪表盘表面把会话内容暴露给非浏览器消费方，因此每条路由都需要 bearer 认证。挂到那上面要么会削弱 GUI 服务器已声明的保证，要么必须按消费方把它的路由分叉。先例：ACP 拥有自己的 stdio，`sdk/server` 拥有自己的 HTTP 套接字。接受的代价：部署要多跑一个端口，放在自己终结 TLS 的网关之后。

## 为什么用「白名单 + 未映射即丢弃」

该线路离开了进程信任边界。会话事件映射是可合并扩展的——任何插件都能新增词汇——因此默认全部转发的规则会意外把新载荷（提示词请求头、hook 内部细节、未来携带凭据的事件）泄漏给外部消费方。「丢弃并计数」从构造上就让泄漏方向变得不可能，并用一行调试日志暴露出词汇缺口；给一个新事件建立映射，是本包内一次显式的代码改动。协议里「容忍未知类型」的条款约束的是我们**客户端**的行为，而不是要求我们的服务端去转发。

## 运行中途接入的语义

一个流在某个轮次开启期间接入，会先从已提交的日志状态收到 `MESSAGES_SNAPSHOT`，再加上一个合成的 `RUN_STARTED`，因此即便某次 run 是在客户端连接之前就已经开始的，客户端观察到的 RUN 括号始终是完整配对的。接受的不精确之处：已经开启的那个 step 的分片增量不会被回放；该 step 的 `assistant/message` 会关闭当时存在的任何括号。

## Required verification

- 单元测试套件覆盖翻译的纯粹性（括号配对、丢弃、运行中途合成）、SSE 分帧／保活／溢出隔离，以及常数时间的 token 比较（`tests/`）。
- 包不变量在进程范围内监视实时帧流：发出的类型始终落在 AG-UI 联合类型之内，且 RUN_* 帧遵守 run 的开启状态，一旦违反就在发出时响亮失败。

## Alternatives considered

- **扩展 `SessionEventMap` 以容纳 AG-UI 形状的事件**：在精神上违反了「模型可见 ⟺ 已记录日志」——该投影是展示层，不是会话事实。
- **从既有的 host 网关发出帧**：会在仪表盘消费方的形状稳定之前，把该适配器与 host 的发布节奏和认证模型耦合在一起。

## Consequences

想要仪表盘表面的部署要多跑一个网络监听器，放在自己终结 TLS 的网关之后，而不是共享既有的浏览器 GUI 端口。某个插件引入的每一种新会话事件种类，在有人为白名单添加一条显式翻译分支之前，对 AG-UI 消费方都保持不可见，因此新增的对外可见性是一项主动选择的工作，而不是自动发生的——在适配器被更新以覆盖新引入的内部事件词汇之前，它可能落后于该词汇。在运行中途接入的客户端会收到一个 `MESSAGES_SNAPSHOT` 和一个合成的 `RUN_STARTED`，但不会收到那个已经开启的 step 的分片增量，因此这类客户端观察到的第一个 step，可能渲染成一整块已完成的内容，而不是更早接入者所看到的那种增量流。
