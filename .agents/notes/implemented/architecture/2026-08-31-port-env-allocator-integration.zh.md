# Agent Note：端口/环境分配整合——库加边界 resolve、每进程单实例

Status: implemented

[English](2026-08-31-port-env-allocator-integration.md) | 中文

## Problem

并行会话需要互不冲突的 TCP 端口和会话作用域的环境状态，而每个消费者各自实现的老路每次都会重演同一批失败模式：硬编码的区间与其他部署的选择相撞、只信内存预留而不问内核、端口发出去却迟迟不绑定结果被外部进程抢先占住、以及靠改写 `process.env` 或共享基础对象来拼装会话环境。`@deepseek-ai/dsh-port-allocator` 以纯库交付该能力；没有成文的整合模式，每个消费者都会重新决定校验放在哪、实例归谁、绑定何时必须发生。

## Decision

这个包是库，不是服务：没有 `ctx`、没有注册、没有事件。每个消费者都通过同样四个动作组合它，四者合起来就是整合契约：

- **Config 走插件层的 schemastery。** 随部署而变的选项——分配区间、探测上限、探测接口、环境变量名——都是消费插件的经校验 Config 字段，可从 cordis.yml 修改。库从不读取任何配置来源；它只以参数形式接收原始值。
- **resolve 函数放在边界上。** `resolvePortAllocatorConfig` 与 `resolveEnvIsolatorConfig` 是两个模块的配置边界：schemastery 校验结构，resolve 函数拥有值语义（TCP 区间合法、`min < max`、整数探测上限、POSIX 环境变量名、后缀变量不重复、有后缀变量时分隔符非空），并在构造时大声失败——配置错误在任何分配或环境派生之前就被拒绝，绝不在调用时被静默跳过。默认值住在拥有它的 resolve 步骤里（loopback `probeHost` 即先例），而不是散落在调用点。
- **每进程一个实例。** 分配器的预留表是内存态、进程局部的，并发的 `allocate()` 调用在该实例内部串行化——同进程的两个实例不共享预留，可能把同一个端口发给两个会话。拥有它的插件在自己的作用域里只构造一个 `PortAllocator`（和一个 `EnvIsolator`），绝不按请求构造，并在同一实例上通过 `release` 回收端口。
- **allocate 之后立即绑定。** `allocate` 用一次真实 listen 探测可绑定性后随即关闭，因此发出的端口在那一刻确认可绑，但此后只有内存预留保护它。消费者必须在 `allocate` 返回后的下一步就绑定自己的监听；延迟绑定会留下一个窗口，外部进程可能抢先占住端口，而预留描述的端口已无人持有。耗尽以 `PortAllocationError` 抛出并携带全部探测失败记录，区间打满时会逐一说明每个候选为何被拒。

`EnvIsolator` 补齐配对：给定调用方的基础环境与已分配端口，`buildSessionEnv` 返回全新的会话环境——端口变量、可选的会话 id 变量、以及为配置的基础变量加上会话后缀的值——而且模块完全不持有 `process.env` 的引用，父进程环境既不被读取也不被写入。

## Testing

- 包测试逐字段覆盖配置边界，覆盖 allocate/probe/release 循环（含并发分配的串行化）、携带完整探测失败清单的耗尽路径，以及会话环境派生（端口变量、会话变量、后缀变量与分隔符一致性规则）。
- invariant 伴侣注册本包并断言没有额外的运行时关系：库不持有 `ctx`，因此没有归它所有的事件流或注册表可查。

## Alternatives considered

- **把分配器做成 cordis 服务**——暂缓：尚无第二个消费者，而服务形态会迫使每个部署为单个插件可能用到的能力挂上注册机制。库加这份成文模式为将来第二个后端或消费者到来时保留能力缝拆分的选项（`dsh-llm`/worktree 先例）。
- **不做探测直接分配**——拒绝：不在内存集合里的端口可能已被外部进程持有，只有内核知道；探测把本会在会话启动时爆出的 `EADDRINUSE` 转化为携带逐端口理由的分配拒绝。
- **让消费者自己校验**——拒绝：分散的区间与名称检查会在每个消费者里以不同严格度重复出现，调用点里发明的默认值也无法集中修改。resolve 函数是值语义与默认值的唯一居所。

## Consequences

- 组合接线每次都是消费者自己的事：Config 字段、实例所有权与生命周期回收都不由库提供。本模式笔记就是清单；跳过单实例或立即绑定规则的消费者会重新引入库本要关掉的竞态。
- 跨进程分配仍是概率性的：探测收窄但不消除与本分配器之外进程的竞态。跨进程共享区间的部署必须切分区间，或把已知占用种子化进 `inUse`；内核始终是唯一权威。
- 库的零依赖姿态（除免品牌的 stdlib 外）意味着消费者不会经由它获得 schemastery 依赖——插件层本就承载 Config，resolve 函数只接受普通值。
