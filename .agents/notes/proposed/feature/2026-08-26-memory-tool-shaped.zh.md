# Agent Note：工具形态的项目记忆（memory-by-tool-call）

Status: proposed

[English](2026-08-26-memory-tool-shaped.md) | 中文

## 问题

Steve 的 agent 会持续积累操作性知识——会话状态、决策、环境陷阱、规范位置——目前这些散落在各 agent 的聊天历史或临时文件里。参考部署（opencode）证明了这种形态可行：共享 home 下每个工作区一个目录、纯主题 Markdown、自然生长的子目录（`done/`、`todo/`、`spec/`），人类与 agent 共同编辑同一批字节。harness 缺的是 seam：没有任何服务拥有跨项目持久笔记，于是每个席位都在重造存储，且任何笔记对其他席位都不可达。

注入式替代方案（每次请求重算的记忆段）已被 Steve 直接否决：无论是否相关，注入的记忆在每个请求都付出全部体量的 token；一旦变化就污染可缓存前缀；还会模糊模型实际查阅了什么。

## 提案

一个包（`@deepseek-ai/dsh-memory`），三张面孔：

- **服务定义** `ctx.memory`：对存储根（默认 `<harness home>/memory/`）的 read/write/list/search，项目作用域按操作从显式 cwd 解析。内容是普通 Markdown；frontmatter 可选。
- **本地提供方**：文件系统承载；写入经临时文件改名以保护协作读者；任何 I/O 前执行严格路径 jail；完整条目字节上限（256 KiB）；list/search 结果有界。
- **面向模型的工具** `memory`（`{action, path?, content?, query?}`）：作用域取自调用会话头的 cwd；被调用前在提示词中零存在感。

作用域 slug 对齐参考部署的形状——`<工作区目录名>-<sha256(解析后 cwd) 的 6 个 hash 字符>`——同名 checkout 绝不共享笔记，同一 checkout 跨会话、重启与席位共享。

## 备选方案

- **注入式记忆段／自动召回 embedding。** 指令层面已否决：仅限工具形态。暂缓记录把子串搜索作为上限；语义召回日后可作为同一 seam 的新消费者接入而不触动契约。
- **基于会话日志的记忆**（笔记作为会话事件）。否决：生命周期不对。记忆比任何会话活得久且必须跨会话共享；日志按设计属于单个会话。
- **SD 独立成包 + 工具独立成包。** 并入同一切片：今天不存在提供方与消费方各自演化的需求，而无论如何 preset 都需要同一 isolate 组内的两行挂载。

## 后果

- Agent 获得跨会话的项目知识，token 成本只在显式读取时发生；大体量内容留在磁盘上而非上下文里。
- 人类零成本进入循环：笔记是 `$DSH_HOME/memory/` 下的真实文件，可以像任何仓库文档一样编辑和 diff。
- 标准 preset 采用只需三行的 group 块；拒绝记忆的部署直接省略该块，请求缓存目录保持稳定。

## 必需验证

- 无密钥套件：提供方往返、slug 作用域与隔离、jail 逃逸拒绝（`../`、绝对路径、反斜杠、NUL、纯空白）、字节上限、搜索截断与限额——以及工具经真实 ToolRuntime 挂载，对携带 cwd 的会话演练 write→list→read→search，包括无会话拒绝路径。
- 经可运行示例的 REAL 组合快照覆盖留给落地 PR（本切片受指定 write-set 约束）；工具渲染路径在此由单元断言钉住。
